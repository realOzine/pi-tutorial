# 课程大纲：从最小循环到可评测的 coding agent

学习目标是独立搭建 Agent，并能沿着源码和运行轨迹解释它的行为。完成课程后，你应能回答：消息怎样进入模型，工具怎样获得执行权，结果怎样影响下一步，程序怎样停止、恢复，以及哪些复杂度值得保留。

课程以 TypeScript 为实现语言，以 pi 为主要源码参考。mini-SWE-agent 和 DeepSeek Harness 用于比较同一问题的不同解法。框架名称不是课程章节；每次比较必须先说清问题、约束和可观察差异。

00—12 共 13 课已经提供 HTML 教材、学生 TODO、固定场景、检查与独立参考实现。下文列出每课的学习目标和验收条件；具体命令与初始失败说明见对应 `labs/` 的 README，实际运行证据见 [进度记录](progress.md)。教材可用与学生完成是两种状态。

## 学习节奏与成果

每课采用同一学习顺序：具体故障或需求 → 预测消息轨迹 → HTML 单步观察 → 沿 pi 调用链阅读 → 学生补全核心逻辑 → 运行固定场景 → 评阅与取舍记录。先给提示和反例，再按需要查看独立参考解答。

每课结束保留三项材料：学生代码、实际检查或 trace、用自己的话写的一段设计说明。说明至少回答“解决了什么问题、付出了什么代价、什么条件变化时应换方案”。测试通过只覆盖测试列出的条件，不代替解释和真实模型实验。

| 里程碑 | 能完成的任务 | 边界 |
|---|---|---|
| 第 3 课：最小 MVP | 接收任务，调用一个受限工具，根据反馈继续，达到条件后退出 | 一个模型接入、少量工具；尚未包含完整 coding 工作流 |
| 第 7 课：可交互 coding agent | 在实验目录读取、编辑、运行 Node 语法检查，显示增量，响应取消，调度多工具 | 尚未完成持久化、长期上下文和系统评测 |
| 第 12 课：毕业项目 | 恢复会话，管理上下文，加载一个扩展，运行固定评测并解释失败 | 本地 CLI；不承诺生产级隔离、任意代码安全或通用任务成功率 |

## 0. 必要的 TypeScript

**问题与目标。** 同一个函数可能收到用户消息、工具请求或工具结果。如果只用一个没有约束的对象，程序容易把内容交给错误的处理分支。本课掌握后续实验需要的类型与异步语法，不扩展成完整前端课程。

**先修。** 会使用终端、函数、数组和基本控制流。已有 Go 经验时，把 tagged union 理解为“带明确种类标签的数据”，把 `Promise` 理解为异步操作的结果；二者都不等同于 goroutine 或 channel。

**练习。** 按消息的联合类型补全分支；用 `async/await` 调用一个假工具；处理 `unknown` 错误；观察 `AbortSignal` 只通知取消、不会自动终止所有操作。脚手架提供类型与输入，学生写分支和错误处理。

**验收。** 能区分编译检查与运行时输入校验；为新增消息种类补齐处理；解释为什么异步函数不必然并行执行。

**取舍。** 用显式数据类型减少不合法状态，但运行时外部输入仍需校验。只学当前实验用到的语法；复杂泛型和完整 TUI 开发暂缓。

**源码位置。** `packages/agent/src/types.ts` 的 `AgentMessage`、`AgentTool` 和 `AgentEvent`；类型文件已静态阅读。页面单步对照类型收窄、异步结果和取消通知；学生实现 `describeMessage` 与 `runOperation`。

## 1. 最小 Agent 循环

**问题与目标。** 模型说“我要读取 README”并不会让文件自动被读取。程序必须执行工具，把结果加入历史，再请求模型。学生实现这条最短闭环，并决定什么时候停止。

**先修。** 能读函数、对象、数组和 `async/await`。不需要真实模型账号。

**练习。** 补全 `labs/01-agent-loop/loop.ts`。脚手架提供确定性模型场景和受限工具；学生处理请求、工具反馈、历史追加与停止边界。先预测“读文件→收到内容→最终回答”的顺序，再运行代码。

**验收。** 按实际实验契约核对：直接回答时不执行工具；需要工具时，下一轮能看到它的结果；工具失败进入约定的反馈路径；循环受步数上限约束。具体断言以该课测试文件为准。初始 TODO 导致失败属于预期，不能记成练习已通过。

**取舍。** 确定性假模型使控制流可重复，但不证明真实模型会作出正确决策。第一版采用直观的顺序流程，先让数据流清楚，再增加流式和并发；循环预算是课程保护措施，不声称它与 pi 默认行为一致。

**源码位置。** 已静态阅读的 `packages/agent/src/agent-loop.ts:172`（`runLoop`）和 `packages/agent/src/agent.ts:382`（`Agent.prompt`）。HTML 单步展示状态、消息历史、下一次请求和停止原因；模拟轨迹与导入的 Node 运行轨迹明确区分。

## 2. 工具协议与失败反馈

**问题与目标。** 模型请求一个不存在的工具，或把路径传成数组。理解工具声明、调用 ID、参数校验、执行结果和错误反馈之间的协议。

**先修。** 第 1 课；能说明工具结果为什么必须回到模型历史。

**练习。** 实现工具查找、执行前校验与结果关联；注入未知工具、错误参数、执行异常和截断响应。课程提供工具声明、校验函数和异常样本，学生决定在哪一层拒绝与如何反馈。

**验收。** 非法请求不执行工具；结果可关联到原调用；工具失败不被包装成成功；模型拿到足够明确的错误后可以重新尝试。截断响应不执行可能残缺的参数。

**取舍。** 通用校验统一边界，但不能替代工具自身的业务约束。错误反馈保留恢复机会，也会增加轮次与成本。早停、继续和重试应有明确条件。

**源码位置。** 已静态阅读 `agent-loop.ts:718`（`prepareToolCall`）、`:488`（截断调用处理）、`:821`（`runToolCall`）。页面对照未知工具、参数错误、工具异常与截断响应，学生实现 `executeToolCall` 和 `executeResponseTools`。第 04 课再对照已固定版本的 mini-SWE-agent bash 入口。

## 3. 接入真实模型

**问题与目标。** 假模型能固定返回下一步，真实服务可能超时、拒绝请求或返回不同消息结构。保持核心循环稳定，为一个真实 provider 接入适配层，形成最小 MVP。

**先修。** 第 2 课；理解 HTTP 请求、环境变量和错误返回。

**练习。** 补全 OpenAI Responses 的请求编码与响应解码：把内部调用 ID 映射为 `call_id`，把工具结果映射为 `function_call_output`，保留停止原因和 usage。先用本地 HTTP 服务器验证，再显式启用真实模型。凭据从本地读取，不进入 HTML、trace 或 Git。

**验收。** 同一个循环能使用假模型和一个真实模型；保留真实失败与用量信息；错误和取消可区分；超时不会被误报成完成。真实调用单独记录 provider、模型、时间和用量，不靠模型名称推断能力。

**取舍。** 统一接口降低循环与服务商的耦合，却可能掩盖各家的消息、缓存和工具能力差异。课程只支持文本与函数工具，使用 reasoning effort `none`；不声称兼容图片、托管工具或推理项回传。真实入口使用用户指定的 `gpt-6.1-terra`，默认检查保持离线。输出上限和步数约束工作量，不等于账单硬上限。

**源码位置。** 已读 `agent-loop.ts:390`（`streamAssistantResponse`）和 `coding-agent/src/core/sdk.ts:403`（注入 `streamFn`）。已全文阅读 `packages/ai/src/api/openai-responses.ts`，并核对 OpenAI 官方函数调用协议。页面展示“课程消息→provider 请求→课程响应”的对应关系。

## 4. 构建 coding 工具

**问题与目标。** 能执行函数还不足以可靠修改代码：读文件可能太大，编辑目标可能不唯一，命令可能永不结束。构建只作用于实验目录的文件与命令工具。

**先修。** 第 3 课；知道参数校验不是权限隔离。

**练习。** 接入 `read_file`、`write_file`、`edit_file`、`check_file`。学生实现路径与链接边界、恰好一次的文本替换；脚手架提供有界 I/O、取消和超时。`check_file` 固定运行 Node 语法检查，不执行被修改程序。使用课程样例，不操作 pi 源仓库。

**验收。** 拒绝越出实验边界的路径；替换不唯一时保留原文件；非零退出码和超时明确返回；输出截断可识别。验收不能只检查字符串前缀，还要覆盖实际采用的路径与符号链接规则。

**取舍。** 少量通用工具易理解，专用工具能减少参数歧义。进程工作目录只决定相对路径，不构成 sandbox；开放任意 shell 前必须确定并验证隔离方案，不能用“只在实验目录启动”代替它。

**源码位置。** 已全文阅读 `packages/coding-agent/src/core/tools/{read,write,edit,bash}.ts`、`file-mutation-queue.ts` 与 `edit-diff.ts`。页面对照 pi 的文件队列和模糊匹配，以及 mini-SWE-agent 的原生 bash tool calling。课程采用更窄的严格替换和命令范围，避免把工作目录说成隔离。

## 5. 流式输出与事件

**问题与目标。** 等全部工作结束才输出结果，用户无法判断程序正在生成、执行工具还是卡住。把模型增量、完整消息、工具状态和运行状态分开。

**先修。** 第 4 课；能辨别一次模型响应与完整任务的区别。

**练习。** 实现 `consumeStream`，累积文字和原始工具参数，只在完整结束时提交。用本地 SSE fixture 验证跨网络 chunk 的解码；真实 Responses 适配另外映射 `item_id` 与 `call_id`。故意放慢监听器，观察后续读取是否等待它。

**验收。** 增量不会重复写入最终历史；工具参数未完成时不执行；完整消息与 UI 状态一致；监听器失败和运行结束有明确处理方式。

**取舍。** 流式降低等待感但增加中间状态。事件既可只供观察，也可作为下一阶段必须等待的屏障；必须说明哪一种会影响执行时序。

**源码位置。** 已读 `agent-loop.ts:390` 和 `agent.ts:575`（`processEvents`）。pi 原始循环事件流与 `Agent.subscribe()` 的等待行为不同。页面同步展示事件、临时参数和已提交消息；实验用异步流验证执行顺序。

## 6. 中断与用户介入

**问题与目标。** 用户在工具运行时输入“停止”或“做完后再总结”，两者不能进入同一个未经定义的队列。实现取消、运行中引导与完成后的追加任务。

**先修。** 第 5 课；理解 `AbortSignal` 的传播。

**练习。** 学生实现队列排空时点和取消传递；在模型等待、工具执行及轮次边界注入输入。脚手架提供可控制完成时间的假操作。

**验收。** 取消后不启动新的工具；需要取消的操作真正收到信号；引导消息在约定边界生效；追加任务不抢占当前工作。说明已经产生的文件或进程副作用如何处理。

**取舍。** 在轮次边界接收引导便于保持历史完整，却不提供立即抢占。取消通知也不能撤销已完成副作用；“任务停止”与“所有外部影响撤销”是不同承诺。

**源码位置。** 已读 `packages/agent/src/agent.ts` 的 `steer`、`followUp`、`abort`、`continue`，以及 `agent-loop.ts:172`。页面在不同阶段插入同一条消息，比较 steering、follow-up 与 abort；实验核对模型和工具实际收到的信号。

## 7. 多工具调度

**问题与目标。** 同一响应请求读取两个独立文件时可以并行，但先写后读同一文件需要顺序。实现有明确依赖规则的多工具执行，形成可交互 coding agent。

**先修。** 第 6 课；理解并发开始、完成顺序和记录顺序。

**练习。** 实现顺序与并行执行；先预检，再执行获准的请求；学生保留调用与结果关联，并决定结果如何进入模型历史。对依赖性操作提供顺序场景。

**验收。** 独立任务允许重叠；需要顺序的任务保持约定顺序；一次失败不吞掉其他已完成结果；取消路径不启动尚未获准的工作；运行结束后无遗留任务。

**取舍。** 并行减少等待，却增加资源占用和副作用竞争。pi 当前默认并行，一项工具声明 sequential 就让整批串行：规则简单，代价是可能牺牲批内其他工具的并发。

**源码位置。** 已读 `agent-loop.ts:518`、`:540`、`:596`。该版本完成事件按结束顺序发出，最终工具消息保持模型调用顺序。页面用时间线比较两种顺序；页面模拟时长不作为性能测量。交互入口 `node labs/07-scheduling/coding-demo.ts --interactive` 连接真实文件工具，支持 `/start`、`/steer`、`/follow`、`/stop`；模型仍是固定规则。

## 8. 会话与恢复

**问题与目标。** 程序退出后，内存里的消息消失。直接重放历史又可能重复修改文件。区分持久化记录、模型所见上下文和有副作用的工具执行。

**先修。** 第 7 课；理解工具调用和结果必须配对。

**练习。** 学生实现 `projectSession`：沿 `parentId` 选择分支，检查工具配对，把结果未知的调用标成 `needs_review`。脚手架提供真实 JSONL 追加、文件 `fsync` 和尾行恢复；原文件保留，恢复另写新文件。

**验收。** 正常关闭后可恢复；损坏或半写入记录有明确处理；未知结果的副作用操作不自动重复；恢复后的上下文不出现孤立工具结果。进程崩溃与断电持久性分别说明。

**取舍。** 追加日志易追溯，但读取、分支和版本迁移更复杂。保存对话不等于持久化任务调度，也不保证 exactly-once（外部副作用恰好执行一次）。

**源码位置。** 已全文阅读 `packages/coding-agent/src/core/session-manager.ts` 和 `docs/sessions.md`，对照追加、分支和消息投影。页面区分持久日志、当前模型历史和待人工核对的工具意图。课程采用单进程写入；`packages/durable` 不属于这个调用链，也没有被本课运行验证。

## 9. 上下文管理

**问题与目标。** 工具输出不断增长，模型窗口、成本和检索质量都会成为限制。理解每次请求包含哪些材料，并比较截断、摘要和按需读取。

**先修。** 第 8 课；能从持久记录构造本轮请求。

**练习。** 实现 `selectContext` 的全量、按完整用户轮次裁剪、摘要三种策略，保留来源索引和原始记录。课程预算使用序列化消息的 UTF-16 长度，不冒充 provider token 计量，也不包含系统提示和工具声明。固定摘要器演示如何丢失关键条件。

**验收。** 请求符合选定预算；消息与工具结果不被拆坏；摘要失败不破坏原始记录；能指出质量改变发生在哪个任务。token 估算与 provider 实际计量分开记录。

**取舍。** 裁剪便宜但可能删除依赖，摘要保留更多语义却会有损失并增加调用成本，按需读取降低常驻内容却增加工具往返。Embedding 只有在具体检索问题出现后才作为候选。

**源码位置。** 已读 `agent-loop.ts:399` 的 `transformContext` / `convertToLlm` 边界；已全文阅读 `packages/coding-agent/src/core/compaction/compaction.ts`。参考 Anthropic 上下文工程文章，作者建议与本地实验结果分开。页面比较同一请求在三种策略下可见的信息，摘要质量结论只针对给定样例。

## 10. 指令与扩展

**问题与目标。** 每加一个行为都修改循环，核心会逐渐混入项目约定和工具细节。区分提示词、项目指令、skill、工具和扩展 hook 的职责。

**先修。** 第 9 课；能描述循环、上下文与工具的接口边界。

**练习。** 实现启用过滤、工具注册、顺序上下文 hook 和逆序 dispose，接入项目说明与 `project_info` 工具。指令文本由调用方显式提供，不自动扫描或下载。MCP 只比较进程内、stdio 与 HTTP 边界，本课程没有实现 MCP 客户端。

**验收。** 禁用扩展后核心实验仍通过；扩展异常可定位；加载顺序和重名规则可说明。指令文本不能自行获得工具执行权；扩展代码则是同进程的可信代码，不构成权限隔离。

**取舍。** 扩展降低核心修改频率，却增加生命周期、配置、加载顺序和调试成本。对比 pi 的扩展机制与 DeepSeek Harness 的 Cordis 插件组合，先看同一需求，不比较功能数量。

**源码位置。** 已全文阅读 `coding-agent/src/core/sdk.ts`、`core/extensions/runner.ts`、`core/resource-loader.ts` 和 `docs/mcp.md`。DeepSeek 对照固定到 `f3803c9`，全文阅读 `packages/core/agent-loop/src/index.ts` 的服务与工厂装配；没有据此宣称读完其具体驱动或整个仓库。页面展示一次请求经过的 hook 顺序。

## 11. 评测与可靠性

**问题与目标。** 一个示例成功无法说明改动有效；失败可能来自循环、工具、上下文或模型。建立固定任务与失败分类，用证据选择改动。

**先修。** 第 10 课；已有可保存的运行轨迹和受限实验项目。

**练习。** 实现固定任务的判定与报告，区分“任务符合预期”和“循环正常完成”，缺失 usage 或价格时保留未知。对基线与候选做成对比较，按失败阶段分类；课程样例不调用真实模型，不能据此报告真实模型成功率。

**验收。** 有明确基线、版本与配置；结果可复查；测试失败能定位到一层；测量包含完成率、调用数、延迟和成本或其不可用原因。确定性检查与真实模型的重复实验分别报告。

**取舍。** 精确断言适合协议，任务质量可能需要人工判断。小任务集迭代便宜，但样本偏差大；本课不把少量成功案例换算成通用能力排名。

**源码位置。** 已全文阅读 `packages/coding-agent/test/suite/harness.ts`，以及 `8935-parallel-preflight-abort.test.ts`、`11227-recovery-omits-tool-results.test.ts` 两个回归案例。页面从结果表追到失败层；本课程没有执行 pi 的测试套件。

## 12. 整合与架构答辩

**问题与目标。** 单个模块各自通过仍可能在组合时出错。把课程成果接成一个只在限定实验环境运行的 CLI coding agent，并说明每一项能力为何存在。

**先修。** 第 11 课；前述实验的核心逻辑由学生完成并经过评阅。

**练习。** 实现 `runAgent`，装配前面各课的实际模块。读取 README 与 `greeting.mjs`，修复语法、运行检查、解释结果；中途按步数停止，再重新打开日志继续。扩展开关和上下文策略进入同一条路径，真实模型通过显式 CLI 选项启用。

**验收。** 以最终文件精确内容和独立 `node --check` 判定任务，不能用模型自评。意图先落盘，工具批次结束后结果才落盘；取消或崩溃留下未知结果时拒绝自动重放。恢复已完成对话不主动发新请求。学生能从输入追到 HTTP、子进程和日志，并解释 `completed` 与验收通过的差别。

**取舍。** 毕业项目追求可理解和可验证。对不需要的多 Agent、后台任务、分布式执行和完整 TUI，不为对齐框架功能而实现；若某个需求确实需要它，先写出缺失机制与预计代价。

**源码位置。** 回到已读 `coding-agent/src/core/sdk.ts:191`、`agent.ts:382`、`agent-loop.ts:172`；课程 CLI 的装配以自身源码和集成检查为证据，没有声称复刻 pi 的完整 CLI。对照 pi 的循环与会话、mini-SWE-agent 的工具入口、DeepSeek 的扩展装配；比较范围随已核验的源码确定，不给脱离任务的总排名。

## HTML 与代码实验如何配合

HTML 承担讲解、预测、单步播放和轨迹检查。Node 实验承担真实 TypeScript 执行、断言和 trace 输出。浏览器不会为了播放动画执行任意本地 shell；源码编辑仍在编辑器中进行。

教学模拟必须标记为模拟，固定假模型的运行必须标记为固定场景，真实 provider 调用必须有模型与运行信息。页面展示的模型决策是外部可见消息或教学设定，不声称展示模型内部思维。

所有课都保留本课问题、状态与消息、源码位置、练习、验收、取舍和来源。00—12 页面均提供可单步的教学场景；第 01 课还支持导入 Node trace。浏览器交互、视觉和 Zed 实际唤起的验证范围单独记在进度记录中。

网页中的代码按钮直接打开 Zed，格式为 `zed://file/绝对路径:行:列`。pi 使用 `/Users/ozine/Project/learn/pi/`，课程源码使用 `/Users/ozine/Project/learn/pi-tutorial/`，均指向日常使用的代码位置。发布页面前检查文件存在、行号有效；GitHub permalink 放在来源说明中，不替代站内代码跳转。
