# 实验与评阅约定

评阅要确认两件事：代码在规定条件下正确运行，学生也能解释为什么这样运行。课程提供场景、协议、测试和提示，学生实现核心决策；参考答案保存在 `solutions/`，与 `labs/` 分开。

## 一次练习怎样完成

1. 先阅读本课问题，手写或口述预期轨迹。说明模型、循环和工具各自负责什么。
2. 在 HTML 中单步观察同一场景，指出与预测不一致的地方。
3. 阅读本课指定的 pi 函数及调用方，确认关键数据从哪里来、到哪里去。
4. 补全学生文件，运行本课检查。优先根据失败证据修正；提示从输入输出关系开始，不直接替换核心代码。
5. 提交代码差异、检查输出、必要的 trace，以及一段取舍说明。
6. 评阅后修改，并重新运行受影响的检查。最后再比较独立参考实现；不同写法只要符合契约且能解释，不要求逐行一致。

第 1 课的学生入口是 `labs/01-agent-loop/loop.ts`，检查命令为 `npm run lab:01:test`。初始 TODO 应当失败；这说明练习尚未完成，不是课程需要偷偷补成答案的理由。

## 第一课怎样判断完成

学生需要能追踪以下过程：用户消息进入历史，模型返回最终回答或工具请求，程序执行工具，将结果关联到请求，再决定下一次模型调用或退出。验收依据是本课协议和测试，不根据答案看起来像 pi 判断。

| 检查方面 | 要看的证据 | 常见误判 |
|---|---|---|
| 控制流 | 直接回答、工具调用、工具失败、步数用尽的实际轨迹 | 只跑了一个成功场景就认为循环完整 |
| 消息协议 | 下一轮能看到需要的工具结果，调用与结果关联正确 | 工具已经运行，却没有把结果交给模型 |
| 停止边界 | 停止原因明确，达到预算后不再调用模型或工具 | 用无限循环等待模型“自行结束” |
| 可读性 | 从入口按执行顺序能读懂状态变化 | 为简单循环拆出大量一次性包装函数 |
| 理解与取舍 | 能解释假模型、顺序执行和步数上限的用途与限制 | 把教学简化说成 pi 的默认设计 |

测试通过后，再提出一个未在成功示例中出现的小变体，例如模型连续两次要读文件，或工具第一次失败。学生先解释预期，再决定是否需要新增测试。评阅不靠背诵答案，也不要求无关重构。

## 检查结果要分开记录

`npm run check` 用于课程工程的类型、站点与基础设施检查，并运行参考实现的实验验证。`npm run lab:01:test` 检查学生实现。两者的结论不能互相替代：课程检查通过时，学生 TODO 仍可能未完成。

参考演示使用：

```sh
npm run lab:01:demo -- --scenario readme --trace artifacts/lesson-01.json
```

它生成的是参考实现运行固定场景的证据。轨迹可以帮助理解协议，但不证明学生实现正确，也不证明真实模型能成功完成同一任务。若以后使用真实模型，报告必须另写 provider、模型、配置、运行时间、用量、成功和失败样本。

| 材料 | 能说明什么 | 不能说明什么 |
|---|---|---|
| HTML 教学模拟 | 课程设定下的状态与消息变化 | Node 实现已执行，或真实模型会作出同样决策 |
| 固定场景的 Node trace | 指定实现按记录走过哪些步骤 | 未记录的代码路径正确，或真实任务成功率 |
| 测试输出 | 被测试的断言在该环境下是否成立 | 全面安全、性能优势或生产适用性 |
| 真实模型运行 | 指定配置下该次任务的实际行为与用量 | 换模型、换任务后仍有相同表现 |
| 静态源码阅读 | 当前版本可见的控制流和约束 | 完整系统已经端到端跑通 |

导入的 trace 是外部数据，应经过格式与大小等约束检查。即使格式合法，内容也只是提供者提交的记录；页面不得把任意导入文件标成已认证的运行证据。模型的外部消息和工具决策也不等于可读取的内部思维。

## 反馈如何给

先指出影响正确性的具体问题，再给最短反例和修改方向。例如“第二轮请求只包含工具结果，丢掉了原始任务；把两轮请求并排看，确认需要保留哪些消息”。避免只说“状态管理不好”或直接重写全部答案。

反馈分成三种：必须修正的协议或行为错误、需要补充证据的未知项、可选的可读性建议。每次优先解决少量阻塞理解的问题，不把尚未讲授的扩展机制塞进当前练习。

一份评阅记录至少写明：

- 检查的是学生实现还是参考实现，使用哪次代码和哪个场景。
- 运行了什么、实际结果是什么；未执行项明确写待验证。
- 最重要的反例、修正理由和复查结果。
- 学生对取舍的解释，以及进入下一课前还欠哪项能力。

## 后续课程保持的边界

真实模型调用不进入默认测试。文件和命令实验使用专用目录、固定输入和可恢复样例；不能把 shell 的工作目录当成安全隔离。课程新增工具前先规定权限、输出、失败和取消契约，再编写相应验收。

每课保留可独立查阅的讲解与实验说明。学生已有实现不会因生成下一课或更新参考解答被覆盖。完整大纲是学习路线；只有实际交付、检查并记录的课程内容才标记完成。
