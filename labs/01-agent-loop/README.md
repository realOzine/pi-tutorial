# 第一课：让工具结果进入下一次模型调用

任务是“读取 README，告诉我项目名称和启动命令”。模型说“我先看文件”并不等于任务完成：程序还得执行它请求的工具，把结果加入消息，再次调用模型。本课由你补全这段控制流程。

在课程根目录运行，使用 Node.js 24。模型和 README 都是内存中的教具，无需 API Key，不会调用付费模型、执行 shell 或读取你的项目文件。CLI 导出轨迹时才会写入你指定的 `artifacts/` 文件。

## 先预测，再实现

先写下你的预测：第一次请求包含哪些消息？文件读取结束后，下一次请求多了哪些消息？“助手消息含有文字”能否作为停止条件？预算只有一次模型调用时，工具结果应不应该保留？

只修改 `labs/01-agent-loop/loop.ts` 的 `runAgentLoop`。类型和函数参数已经给出，脚手架负责场景、命令行和轨迹记录，你不需要实现它们。

| 参数或结果 | 含义 |
| --- | --- |
| `initialMessages` | 初始消息，不应原地修改这个数组 |
| `model(messages)` | 接收本轮全部消息，返回助手消息和 `toolCalls` |
| `executeTool(call)` | 返回字符串；失败时抛出异常 |
| `maxSteps` | 最多调用模型的次数；本课输入固定为非负整数 |
| `status` | `completed` 表示模型不再请求工具；`budget` 表示调用次数用完 |
| `messages` / `steps` | 最终完整消息和实际模型调用次数 |

这里的 `completed` 只是循环的结束条件，不证明答案正确或任务真的完成。评测任务成败是后续课程的内容。

需要满足的行为：

1. 每次模型返回的助手消息都进入历史，包括仍带有工具请求的消息。
2. 有工具请求就逐个执行，并通过 `callId` 把每个结果对应到请求。
3. 工具异常变成 `isError: true` 的结果，让模型看到失败；模型自身的异常继续抛给调用者。
4. 没有工具请求才正常结束。文字和工具请求可以同时存在。
5. 次数用完时返回 `budget`。最后一次请求的工具仍执行，结果保留，但不再调用模型。零预算直接返回。

先运行学生测试，初始版本应因 TODO 报错：

```sh
npm run lab:01:test
```

完成后运行默认场景和两个故障场景：

```sh
npm run lab:01
npm run lab:01 -- --scenario tool-error
npm run lab:01 -- --scenario budget
```

`readme` 读取内存 README 后结束；`tool-error` 先读错误路径，再尝试根目录文件；`budget` 会不断请求读取，直到你的循环耗尽两次模型调用额度。它们检验控制流，不检验真实模型是否会自主采取这些行为。

## 观察轨迹与提交

```sh
npm run lab:01 -- --trace artifacts/lesson-01.json
```

在 HTML 第一课页面导入该 JSON，可以逐步检查模型当时看到了什么。导出只接受课程根目录下 `artifacts/` 内的 `.json` 路径，已有文件不会被覆盖；第二次导出请换一个文件名。

提交评审时提供三样东西：你的 `loop.ts`、学生测试输出，以及一段说明——循环为什么继续、为什么结束，工具错误和预算分别如何处理。也可以附上轨迹文件。评审会先指出违反行为约定的地方，再讨论代码是否清楚；测试通过并不代替你的解释。

如果需要观察参考行为，可先运行演示；参考答案在独立文件，不会覆盖你的练习：

```sh
npm run lab:01:demo -- --scenario tool-error --trace artifacts/reference-01.json
npm run lab:01:verify
```

`lab:01:verify` 对参考实现运行同一组行为测试，不代表你已经完成练习。验证学生实现必须使用 `lab:01:test`。测试文件最后一项单独验证公共脚手架，因此 TODO 未完成时它仍会通过。

## 这里暂时省略了什么

本课的 `model` 是按消息返回预设响应的函数；`read_file` 只认识一个内存文件。它们不是模型 API、JSON Schema 校验器或文件沙箱。不要把这个工具直接改成任意文件读取或 shell 执行并当作安全实现。

循环采用顺序工具执行，便于看清调用与结果的关系；代价是独立工具无法并行。预算只限制模型调用次数，不限制每次返回多少工具、工具耗时或费用。真实模型接入、输入验证、取消、权限和预算扩展将在后续课程处理。
