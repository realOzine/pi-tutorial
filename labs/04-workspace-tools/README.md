# 04：读、写、精确编辑与检查

本课首次产生真实文件副作用。demo 和测试只使用自己创建的临时实验项目，完成后删除；模型仍是固定规则，没有远程 API 调用。

```sh
npm run lab -- 04 test
npm run lab -- 04 verify
npm run lab -- 04 demo
```

学生在 `exercise.ts` 实现路径授权与唯一精确替换，HTTP、循环和工具异常处理复用前两课。`workspace.ts` 提供实际文件 I/O、同目录临时文件替换以及 Node 子进程管理。`solutions/04-workspace-tools.ts` 是独立参考策略。

| 工具 | 参数 | 约定 |
|---|---|---|
| read_file | path | UTF-8 文本，输入最多 64 KiB，返回前 4096 bytes 并标明截断 |
| write_file | path, content | 父目录必须已存在；可新建或完整覆盖；内容最多 64 KiB |
| edit_file | path, oldText, newText | oldText 非空且恰好出现一次，重叠出现也算多次；否则不改文件 |
| check_file | path | 仅 .js/.mjs/.cjs 的 Node --check 语法解析；不执行目标程序 |

路径只能相对于传入 workspace，拒绝绝对路径、空段、点段、父目录、隐藏段、反斜线、空字符，以及任意稳定符号链接、非普通文件或多硬链接。只拒绝字符串 `../` 不够；测试覆盖目录链接和最终文件链接。父目录不存在时拒绝，不替模型递归建目录。

读取通过 O_NOFOLLOW 打开最终文件，并限制实际读取字节数；写入先写同目录唯一临时文件，再 rename 到目标，保留现有普通权限位。rename 前取消会保留原目标；rename 后收到取消不代表文件已回滚。没有 fsync，因此不承诺断电持久性；不保存旧版本，恢复能力依赖后续日志或外部版本管理。

这是**稳定、可信实验目录的应用层边界**，不是操作系统 sandbox。不抵抗同机进程在检查和使用之间替换父目录的竞争；不支持不可信共享目录。环境隔离需要额外 OS/容器机制。本课不开放任意 shell：check 固定 Node 可执行文件、固定参数、空环境，并通过 stdin 发送已读取源码，防止 NODE_OPTIONS 注入预加载。

check 成功返回 exitCode=0；非零退出、超时与取消分别报告。默认期限 2 秒，输出最多 4096 bytes 并保留截断标记。它只证明语法可解析，不证明运行行为、测试用例或业务正确。`.js` 和 `.mjs` 按 module 解析，`.cjs` 按 commonjs 解析，不自动模拟项目全部构建配置。

学生 TODO 初始导致功能测试失败；子进程公共脚手架测试可能通过。提交路径策略与替换逻辑、失败前后文件内容、测试输出。解释为什么旧文本出现两次时要拒绝，为什么 cancellation 不等于 rollback，为什么 node --check 成功不能写成“测试全部通过”。
