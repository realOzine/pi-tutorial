从一个循环，
理解 Agent 如何工作。

你告诉模型“读一下 README”，究竟是谁打开文件、把结果交回模型，又是谁决定结束？这门课从这条最短的执行路径开始，一步步搭建自己的 Agent，并回到 pi 的源码核对真实实现。

每次增加一个机制，都先回答它解决了什么问题。你将亲手写关键代码，观察运行轨迹，再讨论这个选择付出的代价，以及何时应该换一种做法。

02怎样完成一课

先读任务，预测下一步，再操作模拟器。能解释一条轨迹以后，去本地补齐关键代码；测试告诉你具体哪条约定被破坏，源码阅读则帮助你理解真实项目怎样处理更多约束。

  1. 观察：把一次输入到最终输出的消息和控制流串起来。
  2. 实现：只写当前机制，脚手架提供与本课无关的输入输出。
  3. 验证：先用模拟模型检查程序行为，再在后续课程接入真实模型。
  4. 解释：提交代码、测试结果和一段设计说明，接受评审后再进入下一课。

参考实现放在独立的 solutions/ 中。练习不需要先打开答案；卡住时可以逐层展开提示。完成标准是能解释行为，并应对变化的输入。

每课会区分源码事实、教学简化、设计推断与实测结果。课程以固定提交为源码基线；本地 pi 更新以后，需要重新核对链接行号和实现行为。
