你告诉模型“读一下 README”，究竟是谁打开文件、把结果交回模型，又是谁决定结束？这门课从这条最短的执行路径开始，一步步搭建自己的 Agent，并回到 pi 的源码核对真实实现。

01完整课程地图

这是一条逐步扩展同一个程序的路线。前两课建立循环与工具协议，随后接入真实模型和 coding 工具；在程序能够完成任务后，再处理交互、恢复、上下文和扩展。

  1. 00

    读懂本课需要的 TypeScript

    从 Go 的经验出发，认识联合类型、Promise、async/await 与取消通知。只补足读源码和写实验的前提。

    可以学习
  2. 01

    最小 Agent 循环

    模型请求 → 工具执行 → 结果回传。写出循环，区分正常结束、工具错误与步数耗尽。

    可以学习
  3. 02

    工具协议与失败反馈

    参数由谁校验？调用和结果怎样关联？拒绝未知工具、坏参数和截断调用，保留可恢复的错误反馈。

    可以学习
  4. 03

    接入真实模型

    把内部消息映射到 OpenAI Responses，区分 HTTP 失败、取消、截断和 usage；组成最小 MVP。

    可以学习
  5. 04

    构建 coding 工具

    读取、写入、精确替换与 Node 语法检查。验证路径、链接和输出边界，对照 pi 与 mini-SWE-agent。

    可以学习
  6. 05

    流式输出与事件

    消费文本和工具参数增量，区分预览与提交。接入真实 Responses SSE 映射，观察监听器等待。

    可以学习

    中断与用户介入

    沿 HTTP 和工具追踪同一个取消信号，明确 steering 与 follow-up 在何时进入循环。

    可以学习
  8. 07

    多工具调度

    比较完成顺序和结果顺序，处理部分失败与取消；通过 stdin 操作真实文件修改演示。

  9. 08

    会话保存与恢复

    从追加日志投影当前分支，检查半写入尾行和未知副作用，恢复时拒绝自动重复执行。

    可以学习
  10. 09

    上下文选择与压缩

    对同一历史比较全量、裁剪和摘要。保持工具配对、保留原始证据，区分字符预算与 token。

02怎样完成一课

先读具体任务，再从每课的“先看全局，再进入本课”开始。用完整架构建立方向，找到当前深入的部分，然后沿局部流程观察数据怎样变化。理解这条路径后，再读源码和补齐关键代码。

读图顺序这一层要看清什么
1. 完整架构循环、模型、工具、会话等组件各自负责什么，哪些交互跨越进程或网络。
2. 本课位置当前高亮的是哪项职责，输入来自哪里，输出交给谁。
3. 局部流程沿箭头确认调用顺序，以及消息、结果或取消信号的流向。
4. 数据变化先预测再单步，对照状态前后值；区分请求视图、持久日志和实际文件。
5. 架构取舍比较所选方案与另一方案，解释收益、代价，以及何时值得换方案。

例如上下文课会同时展示“请求视图变短”和“原始日志保持不变”。先看懂这两个状态，再读裁剪代码，就能判断它省下了什么、是否丢掉下一步需要的约束。全图保留后续模块便于定位，不表示它们已经在本课实现。

  1. 观察：按上面的顺序读图，再预测一次输入到最终输出的消息和控制流。
  2. 实现：只写当前机制，脚手架提供与本课无关的输入输出。
  3. 验证：先用固定场景检查协议，再检查真实文件或 HTTP；真实模型用量和结果另作记录。
  4. 解释：提交代码、测试结果和一段设计说明，接受评审后再进入下一课。

参考实现放在独立的 solutions/ 中。练习不需要先打开答案；卡住时可以逐层展开提示。完成标准是能解释行为，并应对变化的输入。

每课区分源码事实、教学简化、设计推断与实测结果。课程以固定提交为源码基线；本地 pi 更新以后，需要重新核对链接行号和实现行为。

03三个运行里程碑

第 03 课把循环和模型协议接成 MVP；第 07 课用真实文件工具与 stdin 形成交互演示；第 12 课再连接日志、上下文和扩展，停止后重新打开会话继续完成任务。每一层都沿用前面明确的接口。

npm run lab -- 03 demo
node labs/07-scheduling/coding-demo.ts --interactive
npm run lab -- 12 demo

这些命令默认使用独立参考实现与固定模型。学生检查用 npm run lab -- 课号 test，初始 TODO 应失败。真实模型入口、预算和实际验证记录见第 12 课；模型说“完成”之后，仍要用实际文件和检查结果验收。

文件实验只提供受限工具，Node 语法检查不会运行目标程序。工作目录不是操作系统隔离；课程没有承诺任意代码安全、跨进程恢复或通用任务成功率。
