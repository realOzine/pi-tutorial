04 / 文件与进程

第一次真实改文件执行前后对照路径与执行边界编辑和取消pi 工具实现动手实验取舍与评阅

第 04 课 · 从内存教具到真实副作用

让 Agent 修改文件，
先定义它什么时候不能改。

模型已经能请求工具了。现在给它一个有语法错误的 greeting.mjs：先读文件，唯一替换错误文本，再调用 Node 检查。你的代码必须在路径越界、目标不唯一或用户取消时，拒绝开始不该发生的写入。

先修：第 03 课实验：真实临时文件 + Node 子进程模型：固定规则，无付费调用

错误消息变成文件损坏之前

假设文件里两处都有 enabled = false，模型只要求“把 enabled 改成 true”。直接 replace 第一次出现的位置可能修改了错误对象；全部替换又可能改变另一个功能。工具并不知道业务意图，不能替模型猜。更清楚的契约是要求旧文本唯一，不唯一就返回错误，让模型补充上下文。

read_file("greeting.mjs")
  → console.log(greeting;
edit_file(path, oldText="console.log(greeting;", newText="console.log(greeting);")
  → 恰好一个匹配 → 写临时文件 → rename 到原路径
check_file("greeting.mjs")
  → Node --check → exitCode=0

这条轨迹有三种不同证据：模型决定编辑什么，文件工具确认实际写了什么，检查程序确认语法能否解析。最后一项不证明程序业务正确。不要把“模型说已修复”或“语法检查成功”写成“所有测试通过”。

把拒绝执行也放进时间线

以下是教学模拟；终端 demo 会运行真实文件工具与 Node --check。先预测每条轨迹最后的文件内容，再点击下一步。

路径检查与操作系统隔离不是同一件事

本课由宿主传入一个可信的实验目录。模型只能提供相对路径，不能自己选择 workspace。路径检查逐段拒绝空段、点段、父目录、隐藏段、反斜线与空字符；再通过 lstat 检查每个真实目录项，拒绝符号链接、非普通文件与多硬链接。写新文件时，只有最后一段可以不存在。

为什么不能只检查 resolved.startsWith(root)？一是相邻目录可能有相同字符串前缀；二是目录中的符号链接能把实际访问引到外部；三是硬链接让不同路径共享同一文件对象。先把拒绝策略写成契约，再用真实文件系统样本验证，不要只测试字符串。

本课承诺的边界

工具针对稳定、可信的单用户实验目录，拒绝已存在的路径别名。它不抵抗另一进程在检查和使用之间恶意替换父目录，也不是操作系统 sandbox。需要运行不可信仓库或任意 shell 时，应另行选择容器或 OS 隔离，并验证整个文件、网络与进程权限。

check_file 没有 command 参数。它使用当前 Node 可执行文件和固定 --check 参数，通过 stdin 发送已经读到的源码；子进程环境为空，避免 NODE_OPTIONS 注入预加载。它没有运行目标程序、导入目标依赖或执行 npm scripts。这样的能力够本课检查语法，代价是不能验证业务行为。

输出边界也是工具契约的一部分

一个大文件可能占满模型上下文。本课最多读取 64 KiB UTF-8 输入，read_file 只返回前 4096 bytes 并标明截断；写入内容同样受 64 KiB 限制。超限时明确拒绝或标记，不能让模型误以为看到全部文件。读取使用有界缓冲区，避免仅在读完整个文件后才发现太大。

这些数字是便于实验的课程限制。pi 面向真实项目，提供偏移读取、行数与字节限制等更丰富能力。第 09 课会解释为什么输出限制直接影响下一轮模型能看见什么。

先计算新内容，再提交一次变化

学生函数 replaceExactlyOnce 是纯函数：收到原文、旧文本和新文本，只返回新内容或抛错，不直接写文件。这样可以在任何副作用发生之前验证唯一性。例如 aaaa 中的 aa 有重叠匹配；不能只按不重叠 split 的次数决定是否唯一。

文件层随后把新内容写到同目录的唯一临时文件，再 rename 到目标。对稳定目录而言，这避免读者看到普通覆盖写入中间的半截内容；现有普通权限位会保留。这里没有 fsync，因此不承诺断电后一定保存；也没有旧版本备份，因此不能宣称自动回滚。

取消需要落到具体操作

文件系统调用不一定能在进行中立刻停止。本课在 await 前后检查 signal，rename 前取消会清理临时文件，rename 后取消只能停止后续动作。对 Node 检查进程，取消和超时会终止子进程并等待 close，再完成工具调用，避免把“发了 kill 信号”当成“进程已经退出”。

读与检查都可能失败，错误仍通过第 02 课返回给模型。用户取消则向外传播；它不是让模型继续换命令重试的理由。等到第 06 课，你会在循环层统一看到这些控制路径。

pi 为什么还需要更多代码

打开 read.ts：除了文本，它还处理图片、offset/limit、截断提示和可替换的读操作。它的目标是让同一个工具服务不同模型和文件类型；本课只保留 UTF-8 小文件，减少学习时的分支。

接着读 edit.ts 与 edit-diff.ts。当前 pi 接受多个 edits，在原始内容上匹配并检查重叠；内部还有换行规范化、模糊匹配及未修改行保留。本课只做一次严格字符串替换，故意不把所有容错一起搬进来。增加模糊匹配能容忍模型的空白或字符差异，但也会扩大“什么算同一个目标”的规则，需要更多反例测试。

write.ts 与 edit 都经过 withFileMutationQueue。它按文件串行化修改，并在操作真正结束后释放队列。注释解释了为什么不能在 abort 事件中提前释放：旧写入可能还没结束，新的写入就会与它竞争。

最后看 bash.ts 的 createLocalShellOperations：创建进程、收集输出、处理中止与超时，再检查退出码。它支持通用 shell，能力明显更广。课程的 check_file 是固定检查命令，不能据此推断 pi 的默认工具也受同样路径限制，更不能把 cwd 看成权限隔离。

这些是已读取文件中的事实。关于“专用工具与通用 shell 的取舍”是课程分析：专用工具让参数与失败含义清楚，通用 shell 复用现成生态，但把更多规划和约束留给模型与执行环境。下一步扩展应由实际任务需求决定。

对照 mini-SWE-agent：把操作统一为 bash

mini-SWE-agent 的固定提交 04d809ceab9df28f9adaed044884180159172930 提供了另一条路径。先读本地只读副本 BASH_TOOL 与调用解析：工具声明只有 bash(command)，解析后生成 action，并保留 tool_call_id。这个版本有原生工具调用路径，不能沿用“它一律从文本正则提取命令”的旧印象。

然后沿 step → query → execute_actions 阅读：默认 Agent 把每个 action 交给环境执行，再让模型适配器格式化观察结果。LocalEnvironment.execute 将 command、cwd、环境变量与超时交给子进程；_run 使用 shell=True，并在超时时终止进程组。这里说的是本地环境，不是其他容器后端的隔离承诺。

同一个任务：修改一处文本并检查操作怎样表达约束放在哪里
本课read_file → edit_file → check_file参数、唯一路径与固定命令规则由宿主直接检查
pi 内置工具read/edit/write 配合通用 bash专用工具处理常见编辑规则，shell 承担更广泛任务
mini 的 bash 路径模型组织 shell 命令，环境返回输出与退出状态工具协议简短，操作细节更多交给模型、命令与环境

工程分析：统一 bash 能直接复用 grep、测试器等现有工具，宿主不必为每项功能维护 schema；代价是命令引用、输出解析和执行权限的决策更集中在模型与环境。专用 edit 更容易检查“唯一替换”，但功能范围也更窄。不能仅凭代码行数判定哪种架构更可靠，应该用同一任务与失败样本比较。

完成语义也不同：mini 的这个本地环境在成功输出首行遇到特定提交标记时抛出 Submitted，让循环结束；本课没有工具调用就结束。先明确停止契约，才能正确解释 trace。以上仅为三份固定源码的静态对照，没有运行 mini 的评测。来源、哈希和 MIT 许可证均保存在同目录。

你写路径授权与精确替换

打开 exercise.ts，补全 resolveWorkspacePath 与 replaceExactlyOnce。workspace.ts 提供实际 I/O 与进程管理；你应读懂这部分，但不用重写。测试在独立临时目录中检查真实内容变化。

npm run lab -- 04 test
npm run lab -- 04 verify
npm run lab -- 04 demo

默认 demo 用固定模型执行 read → edit → check → answer。这里模型计划是模拟的，文件写入和 Node 子进程是真实的，结束后清理自己的临时项目。参考成功不表示学生 TODO 已完成。

  1. 路径函数只返回获准的最终文件路径；既有中间段必须是真实目录，不能跟随符号链接。
  2. existing 模式要求最终文件存在；new-or-existing 只允许最后一段缺失。
  3. 旧文本为空、不存在或不唯一时抛错，不计算一个“差不多”的替换。
  4. 保留不相关原文，包括本课没有规范化的换行；确认失败后磁盘内容不变。
提示 1：先区分 lstat 与 realpath

lstat 可以看见路径项本身是否为符号链接。只先 realpath 会失去“路径里出现过链接”的信息，无法执行本课全部拒绝链接的策略。

提示 2：允许创建新文件，不等于忽略所有 ENOENT

只有最后一个组件缺失才可以创建文件。中间目录不存在说明路径尚未获准，不能静默跳过或替模型创建整个目录树。

提示 3：找到第一次之后还要查哪里

从第一次匹配位置加一继续找，而不是加 oldText.length；这样才能发现重叠匹配。确定唯一之后，拼接原文前段、新文本与原文后段。

拒绝链接与隐藏路径实验边界容易说明和测试真实项目常有合法链接、配置文件；放宽前应定义具体授权规则

自测：相对路径 src/link/a.ts 为什么可能越界？

link 可能指向 workspace 外部。字符串规范化不足以判断实际访问目标，需要检查文件系统目录项。

自测：check_file 通过后可以说修复已正确吗？

只能说本课配置下 JavaScript 语法可解析。业务逻辑、运行时依赖和测试行为都没有因此被证明。

自测：rename 后取消，原文件应该是什么？

新内容已经提交，取消不会自动回滚。后续恢复机制必须记录不确定或已完成的副作用，不能假定文件从未改变。

提交学生实现、检查结果和一次失败前后的文件对照。评阅会追加一个未在成功样例出现的输入，例如目录符号链接、旧文本重叠匹配或 `.cjs` 检查，要求你先预测，再运行验证。说明若要允许任意 shell，你必须新增什么边界，不能只改工具描述。
